# بدء تطوير مشترك — Windows وmacOS

المطلوب Git، وPython 3.9+ للأداة ذات المكتبة القياسية، وDocker Desktop يعمل بحاويات Linux (WSL2 على Windows). Python داخل صورة أودو مستقل عن Python المثبت على Windows؛ لا حاجة لتركيب متطلبات أودو أو Node على المضيف لهذا المسار. تأكد من ذاكرة ومساحة مناسبة؛ أوقف بيئة المهمة عند الانتهاء. تثبيت Windows القديم يبقى منفصلاً وغير معتمد مرجعاً.

## النسخ والفروع

استنسخ مستودع الفريق من GitHub Desktop أو Git بعد قبول دعوة الوصول. أثناء مراجعة التسليم اختَر فرع `saif/source-handoff`؛ بعد دمجه اسحب main وافتح فرع مهمتك منه. لا تستبدل تاريخ main ولا ترفع قاعدة بيانات.

```sh
git clone https://github.com/tizx2tr3ip-bit/saif-restaurant-pos.git
cd saif-restaurant-pos
git switch saif/source-handoff
python pilot_ops/team.py init --name ibrahim --port 8072
python pilot_ops/team.py source
python pilot_ops/team.py bootstrap
python pilot_ops/team.py status
```

استبدل python بـ`py -3` إن احتاج Windows ذلك. `source` يجلب المصدر الرسمي المثبت ولا يمس نسخة سيف. إذا فشل التنزيل وبقي checkout غير مكتمل، لا تستخدم إصداراً آخر: عالج الجلب في vendor/odoo ثم تحقق من commit. الأداة ترفض إعادة ضبط مصدر موجود على commit مختلف. يمكن بدلاً منها استعمال Git submodule update بعد تهيئته.

التكوين يتولد في `pilot_ops/.env` و`.runtime/odoo.conf` ولا يُرفع إلى Git. كلمة مرور مدير الديمو مولّدة محلياً في ملف .env؛ لا تنسخها إلى Issue أو PR. تسجيل الدخول `pilot.admin@example.test`. على Windows تأكد من أذونات المجلد حسب حسابك؛ chmod وحده لا يثبت ACL.

التهيئة تنشئ قاعدة `saif_pilot` في PostgreSQL منفصل ضمن مشروع Compose اسمه `saif_team_ibrahim`، ومجلد بيانات Docker خاص به. تنشئ شركة اختبار ومخطط عُمان، كاشير مطعم، طاولات من سيناريو أودو الرسمي، صنفين اصطناعيين بلا ضرائب منتج معتمدة، وقائمة OMR وجلسة مفتوحة برصيد صفر. لا تستعملها كإعداد ضريبي حقيقي. لا تتضمن بيانات طلبات أو صور المطعم أو رموز طاولات سيف. توجد صور افتراضية/غياب صور في الأصناف الاصطناعية؛ هذا ليس استيراد المنيو الكامل.

اقرأ سطر `SAIF_PILOT` في مخرجات التهيئة لمعرفة رقم الكاشير. افتح الإدارة `http://localhost:8072/odoo` والمنيو `http://localhost:8072/cafe/<رقم الكاشير>`، والكاشير `/pos/ui/<رقم الكاشير>`. لا تفترض رقم1 في قاعدة معدّلة. البيانات local؛ روابط localhost لا تفتح من الآيباد أو جهاز زميل.

## اختبار الطلب

```sh
python pilot_tests/smoke_customer.py --config 1 --allow-disposable-orders
```

غيّر الرقم إذا أخرجت التهيئة غير1. الاختبار محصور ببيئة localhost على منفذ مستقل ويرفض منافذ تجربة سيف/Windows الأصلية. ينشئ طلبَي draft غير مدفوعين (سيارة وطاولة) ويحتفظ بهما، ويختبر إعادة إرسال الطلب. لا يثبت الدفع أو الطباعة أو ظهور الواجهة الأصلية بصرياً. اختبارات `custom_addons/saif_cafe_order/tests/` نسخة أصلية مرتبطة بإعداد سيف؛ لا تشغّلها كما هي على بيئتك قبل نقل مساراتها وإعداداتها بواسطة إبراهيم.

## الإيقاف والرجوع

```sh
python pilot_ops/team.py stop
python pilot_ops/team.py up
```

الإيقاف لا يحذف البيانات. لا تستخدم down -v أو prune أو حذف volume أو استعادة فوق قاعدة سيف. النسخ الاحتياطي والاستعادة إلى قاعدة جديدة مهمة إبراهيم التالية؛ لم تتضمن هذه الحزمة سكربت استعادة إنتاجي. لا تعدل إضافة مثبتة بإزالة ملفاتها. احتفظ بنسخة قاعدة + filestore قبل ترقيات مؤثرة.

## تحديث الإضافة بعد تعديلها

تغييرات Python تتطلب إعادة تشغيل app. تغييرات XML/الحقول تتطلب ترقية الإضافة على قاعدة المهمة فقط بعد النسخ الاحتياطي. `bootstrap` مُعد للبدء؛ لا يُستخدم بديلاً عن سياسة migrations. عند إعادة تشغيله على ديمو تم إعداده لا يعيد seed الأسعار أو كلمة المرور أو فتح وردية. لا ترقية عامة لكل وحدات أودو.

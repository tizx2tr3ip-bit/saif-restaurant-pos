# سورس أودو الكامل في مستودع سيف وإبراهيم

استجابة لطلب سيف، حُوّل `vendor/odoo` من رابط Git submodule إلى ملفات مصدر كاملة متتبعة في مستودع التعاون نفسه. الأرشيف مُصدّر من Git الرسمي عند commit `3ab21d47f92a25fd973e0687886a9d3ea5946ed4`، بكامل الملفات المتتبعة وتراخيصها، دون ملفات تشغيل جهاز سيف. المصدر نحو 1.1GB غير مضغوط؛ تنزيل أول نسخة أكبر من السابق.

يبقى تاريخ الفريق السابق دون استبدال. ملفات الإضافات والطلب والمطبخ والتشغيل محفوظة. لا تستنسخ مصدراً آخر داخل المجلد، ولا تستخدم submodule update لهذا الفرع. `source.lock.json` يوثق الأصل وملف `source.snapshot.json` يحصر بصمات كل ملف. أمر `python pilot_ops/team.py source` يتحقق محلياً من النسخة، وbootstrap يستخدم التحقق نفسه؛ لا ينزّل كود أودو مرة ثانية. الصور وحزم التشغيل الخارجية وPostgreSQL ما زالت تُنزّل بالطريقة الموثقة، فوجود السورس لا يعني تثبيت اعتماداته تلقائياً.

لإبراهيم الذي لديه checkout قديم وفيه submodule: احتفظ أولاً بأي تعديلات محلية. الأسهل للتجربة استنساخ المستودع في مجلد جديد ثم اختيار `saif/full-odoo-source` حتى دمجه؛ لا تحذف مجلد عملك القديم ولا تنسخ .env من جهاز سيف. بعد الدمج استخدم main. لا تشغّل بيئتين على نفس المنفذ.

الفرع مبني على تحديث الكاشير والمطبخ، وهذا مبني على التسليم الأول. تُراجع الطلبات وتُدمج بالترتيب، مع تغيير أساس PR التالي إلى main عند دمج سابقه. لا دمج تلقائي.

هذه نسخة Community مفتوحة المصدر مع الاحتفاظ بالتراخيص الأصلية لكل ملف. لا تمثل Enterprise أو جاهزية ميدانية أو اكتمال كل الترجمات. لا تُرفع كلمات مرور أو قاعدة البيانات أو filestore أو نسخة المطعم الحقيقية ضمن هذا التحديث.
